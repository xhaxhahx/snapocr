# 构建与发布指南

## 0. 环境要求

| 平台 | 要求 |
|---|---|
| Windows 构建机 | Windows 10/11 x64，Python 3.10–3.12，联网（拉依赖与模型） |
| Linux 构建机 | UOS 20 / 麒麟 V10 / Debian 10+ 容器，Python 3.8–3.11；**必须与目标系统 glibc 同级或更低**（PyInstaller 不跨 glibc 交叉打包） |

## 1. 准备

```bat
git clone <repo> && cd 截屏ocr工具
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
.venv\Scripts\pip install -r requirements-dev.txt   # 开发工具（ruff），构建机可省
python scripts\download_models.py
```

`download_models.py` **首选**从已安装的 rapidocr wheel 复制其内置默认模型
（rapidocr 3.10 内置 **PP-OCRv6 small** det/rec + `ch_ppocr_mobile_v2.0_cls`）到
`resources/models/det.onnx|cls.onnx|rec.onnx`；ModelScope 直链为尽力而为的备选，
失效不会中断流程（缺模型时引擎自动回落到 wheel 内置模型，功能不受影响）。
模型是**离线发布物**，构建一次即可，之后随包分发。

> 版本核对：`resources/models/*.onnx` 应与 `rapidocr/models/PP-OCRv6_*` 的 MD5 一致；
> 不一致说明拿到了非预期版本，请以 wheel 内置模型为准。

自检（可选但强烈建议）：

```bat
dev.bat --selftest     :: 输出 PASS/FAIL，并生成 docs/screenshots/*.png
dev.bat --bench        :: OCR 耗时基准（不带次数默认 3 次）
```

## 1.1 构建前置检查（2026-10-20 第二轮增补）

- **磁盘**：复制工程 + 产物峰值约 2.5G，建议可用空间 **≥ 3G**。
  空间紧张时的精简复制清单（构建必需，其余可排除）：
  `.venv`、`src`、`resources`、`deploy`、`pyproject.toml`、`requirements*.txt`；
  可排除：`docs`、`scripts`、`.git`、`.tmp`、`build`、`dist`、`.workbuddy*`。
- **复制失败的陷阱**：robocopy 因空间不足中断会留下**看似完整但残缺**的目录
  （典型：`.venv\Scripts\python.exe` 缺失，后续复制因"文件已存在"而跳过，PyInstaller 报
  `The system cannot find the path specified`）。**重试前必须先删除目标目录**，不要在原目录上续传。
- **`robocopy /XD` 的坑（2026-10-20 实测）**：`/XD` 在 Windows 下**大小写不敏感**，
  `/XD scripts` 会连带排除 `.venv\Scripts`（venv 缺 `python.exe`，PyInstaller 报
  `The system cannot find the path specified`）。**必须用绝对路径精确排除**：
  `/XD "$src\docs" "$src\scripts" "$src\.tmp" "$src\dist" "$src\build" "$src\.git"`。
- **`build_all.bat` 必须保持 CRLF + UTF-8(无 BOM)**（文件头注释已声明）：改成 LF 后 cmd
  会把命令行截断（典型报错 `'rofile' 不是内部或外部命令`、`'ld:' 不是内部或外部命令`）。
  用脚本改这个文件时务必按 CRLF 写回。
- 构建完成后清理：`C://snapocr_build`、验证目录、`%TEMP%\_MEI*`（onefile 残留可达 1G+）。

## 2. Windows 双包

> **重要：中文路径下不能直接打包。** PyQt5 的 Qt 插件探测在含中文的路径上会把路径
> 解析成 `??`，导致 PyInstaller 报 "Qt plugin directory does not exist"。
> 解决：把整个工程（含 .venv）**真实复制**到 ASCII 路径（如 `C:\snapocr_build`）后构建
> （junction/subst 无效，Python realpath 会穿透；且必须用
> `python -m PyInstaller` 而非 `.exe` 入口——pip 的 console-script exe 内嵌了创建时的解释器绝对路径）。
> 构建完成后把 `dist/` 产物拷回即可。

```bat
deploy\windows\build_all.bat
```

步骤：PyInstaller（deploy/snapocr.spec，onedir，`python -m PyInstaller`）→ 压缩绿色版 zip →
调用 Inno Setup（6/7 均可）的 ISCC 编译安装版。若未装 Inno Setup
（`winget install JRSoftware.InnoSetup` 或官网下载静默安装 `/VERYSILENT`），
脚本会跳过安装版并提示。

产物：

```
dist/snapocr-win64/                      绿色版目录
dist/SnapOCR-1.0.0-win64-绿色版.zip
dist/SnapOCR-1.0.0-win64-setup.exe       per-user 安装（无需管理员）
```

要点：
- spec 内 `collect_all('rapidocr'/'onnxruntime')` 确保动态导入与模型配置齐全；
- onedir + 不加 UPX，降低杀软误报；
- 版本信息在 `deploy/windows/version.txt`；安装脚本 `deploy/windows/snapocr.iss`。
- **向导配色跟随系统主题**：`snapocr.iss` 用 `WizardStyle=modern dynamic`（Inno Setup 7 起支持）。
  `dynamic` 让安装向导在系统暗色模式下自动变暗；**去掉它会固定浅色**，暗色系统上安装界面刺眼
  （2026-10-26 用户反馈）。Inno 6 不认识 `dynamic`，用 6 构建时需临时删掉该值。
- **VC++ 运行库（发布必备）**：onnxruntime 依赖 VC++ 2015-2022 x64 运行库，干净系统缺失会
  导致**首次 OCR 直接崩溃**。把 `vc_redist.x64.exe` 放到 `deploy/windows/`（与 `.iss` 同目录）即可——
  安装脚本会自动检测注册表 `HKLM\SOFTWARE\Microsoft\VisualStudio\14.0\VC\Runtimes\x64`，
  未安装时静默安装（`shellexec` 以便触发 UAC 提权）。**若该文件不存在，构建与安装都不会失败**
  （`skipifsourcedoesntexist` + `Check` 双保险），但干净机器上会退回"需自行安装运行库"。
  下载：<https://aka.ms/vs/17/release/vc_redist.x64.exe>
- **包体瘦身**：spec 已过滤 `a.datas`，只保留 `platforms/`、`styles/`、
  `imageformats/{qico,qpng,qjpeg}` 三个 Qt 插件目录，剔除 `translations/` 与其余死目录
  （约 −8~10MB）。**不要**去过滤 `a.binaries`——`Qt5Network.dll` 是单实例 IPC 依赖，误删会导致无法启动。
- **`.iss` 必须是 UTF-8 带 BOM**：脚本内含中文（`[Tasks]` 的中文描述等）。Inno Setup **6.3 以前**的
  编译器不会自动识别无 BOM 的 UTF-8，会按 ANSI 解码并报 `Missing closing quote on parameter "Description"`
  （已实测：6.0.5 报错，6.7.3 正常）。**请勿用会丢 BOM 的编辑器保存该文件**。
- **`.bat` 必须 UTF-8 无 BOM + CRLF + `chcp 65001`**：cmd 按**当前控制台代码页**解码批处理，
  中文 Windows 默认 936(GBK)。UTF-8 中文被按 GBK 误读后，其字节序列里的 `\`、`|`、`&` 会把命令行
  截断，表现为 `'请先按 docs' 不是内部或外部命令`、路径被吃掉等**莫名其妙的解析错误**（已实测）。
  因此 `build_all.bat` 首行 `@echo off` 之后必须紧跟 `chcp 65001 >nul`；行尾必须 CRLF
  （LF-only 在部分 cmd 版本下行为异常）。新增批处理脚本一律照此办理。
- **模型随包说明（体积影响）**：`resources/models`（det/cls/rec ≈31MB）会与
  `_internal/rapidocr/models`（rapidocr wheel 内置的同一套 PP-OCRv6 模型）**各打一份**，
  因此三个产物比不加 `resources/models` 时大约 **+30MB**。若需极致瘦身，可从三份 spec 的
  `datas` 中移除 `resources/models` —— 引擎会自动回落到 wheel 内置模型，功能不变（见 §6 验证）。

### 无 Inno Setup 环境下的构建（便携 ISCC）

构建机不能安装 Inno Setup（无管理员权限 / 受限环境）时，可用 innoextract 解出**便携版 ISCC**，
无需安装：

```bat
:: 1) 取 innoextract（Windows 版），并下载 Inno Setup 安装包
::    注意 innoextract 1.9 只支持到 Inno Setup 6.0.5，故取 6.0.5 安装包
curl -L -o innoextract.zip https://github.com/dscharrer/innoextract/releases/download/1.9/innoextract-1.9-windows.zip
curl -L -o innosetup-6.0.5.exe https://github.com/jrsoftware/issrc/releases/download/is-6_0_5/innosetup-6.0.5.exe

:: 2) 解包（7-Zip 解开 zip；innoextract 解开 Inno 安装包）
7z x -o./ie innoextract.zip
.\ie\innoextract.exe -e -d .\is605 innosetup-6.0.5.exe

:: 3) 6.0.5 自带语言文件里没有中文，需补一份同版本的中文 .isl
::    取自 issrc 仓库 is-6_0_5 标签：Files/Languages/Unofficial/ChineseSimplified.isl
::    放到 .\is605\app\Languages\ChineseSimplified.isl

:: 4) 直接调用便携 ISCC（等价于 build_all.bat 的第 4 步）
.\is605\app\ISCC.exe deploy\windows\snapocr.iss
```

> 版本提醒：中文语言文件必须与编译器版本匹配。6.5.0+ 的 `ChineseSimplified.isl` 配合 6.0.5 会因
> 消息名不匹配而报错，请取 `is-6_0_5` 标签下的同名文件。

### 可选：单文件 exe（onefile）

`deploy/snapocr-onefile.spec` 可产出单文件版（约 149MB）。实测代价：**每次启动
都要解压整包到临时目录，本机（2核）实测 ~2.4s/次**（onedir 为 0.16~0.22s），
且自解压形态更易被杀软误报。适合"偶尔用、不想装/不想常驻"的场景；
日常推荐仍是安装版/绿色版 + 开机自启（常驻托盘，呼出零等待）。

```bat
python -m PyInstaller --noconfirm --clean deploy\snapocr-onefile.spec
```

## 3. Linux（UOS/麒麟）deb

```bash
# 在 UOS 20 / Debian 10+ 构建机或容器内
python3 -m venv .venv && .venv/bin/pip install -r requirements-linux.txt
bash deploy/linux/build_deb.sh --arch amd64     # aarch64 构建机上用 --arch arm64
```

产物 `dist/snapocr_1.0.0_<arch>.deb`，安装到 `/opt/snapocr`，
带桌面入口与 `snapocr` 命令。onnxruntime/PyQt5 均选 manylinux2014 兼容版本，
glibc ≥ 2.17 可运行，覆盖 UOS 20 (2.28)、麒麟 V10 (2.31) 及其后版本。

## 4. CI 一键三平台

`deploy/ci/github-actions.yml`：windows-2022 出 Windows 双包；ubuntu-20.04 出 amd64 deb；
ubuntu-24.04-arm 出 arm64 deb。打 tag `v*` 触发。
