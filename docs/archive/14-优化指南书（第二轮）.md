## 2. P2 建议（6 项）

### P2-01 橡皮擦光标与实际擦除范围不一致（**体验偏差，优先**）

- **位置**：`ui/editor.py:663`（`_update_eraser_cursor`）vs `ui/editor.py:871`（擦除半径）
- **事实**：
  - 光标直径 `d = max(8, min(128, int(self.line_width)))` → **细档（2px）实际画 8px 圈**；
  - 擦除半径 `r = max(1, int(self.line_width * self.dpr / 2))` → 细档擦除**直径 2px**。
  - 即：**光标圈是实际擦除范围的 4 倍**（细档）、1.6 倍（中档 5px）。用户会以为擦得更大。
- **由来**：第二十六轮把橡皮口径从"半径=档位"改成"直径=档位"（统一笔宽），光标却保留了
  `max(8, ...)` 的可视下限，两者不再对应。
- **建议**（二选一）：
  1. **双圈光标**：内圈画真实直径（`max(2, line_width)`），外圈画 `max(8, line_width)` 作可见性兜底，
     内圈用强调色区分——既所见即所得又保证小档位可见；
  2. **十字准星 + 小圆**：小档位（≤4px）用十字准星表示擦除点，大档位用圆。
- **回归**：探针断言"光标内圈直径 == 擦除直径"（可用 pixmap 像素统计）；目检细/中/粗/加粗四档。
- **风险**：低（仅光标绘制，不影响擦除逻辑）。

- **建议**：不逐个窄化（多数确实需要宽捕获），**统一补一行原因注释**：

### P2-05 `test_fix_probe.py` 结构与规模（可维护性）

- **事实**：1,047 行；`main()` **977 行**；`_quad_sample`(315) 与 `_quad_pm_sweep`(429) 是**两套
  近乎相同的四色底图构造**；`_sweep_move/_sweep_press/_sweep_release` 在 `main()` 内定义。
- **后果**：新增用例只能继续往 `main()` 里堆；变量名（`_got`/`_srv`/`_cl`）全局污染，易冲突。
- **建议**：
  1. 把每个 UX 段抽成独立函数（`def probe_ux16(ctx)` …），`main()` 只负责编排与汇总；
  2. 提取公共工具到 `scripts/probes/common.py`（四色底图、鼠标事件构造、`ctx` 容器）；
  3. 目标：`main()` ≤ 100 行，单文件 ≤ 600 行。
- **依据**：`docs/10 §3`"同一文件累计 3 条以上 P2 升级为 P1"——本条已含 3 个子问题，
  **按规则应升 P1**，但探针是开发资产、不随产品发布，风险为 0 → **维持 P2**，请审阅时确认此豁免。
- **回归**：拆分前后 `PASS=131` 完全一致（用例数不变）。

### P2-06 IPC 收到非法数据会挂起连接（第一轮修复的副作用）

- **位置**：`utils/singleinstance.py` `_try_read`
- **事实**：第一轮 P1-02 改为"仅完整 JSON 才派发"后，**非法/半截数据会一直等待**，直到累计 64KB
  才断开。客户端超时（1500ms）后自行断开，但服务端 `_pending` 仍指向已断开的 socket，
  直到下次连接才被覆盖 → 轻微对象滞留。
- **后果**：不误触发截屏（原缺陷已修），但极端情况下有 1 个死 socket 滞留。
- **建议**：加"连接断开即清理"——`sock.disconnected.connect(self._on_disconnect)`，
  回调里清 `_pending`/`_buf`；或在 `_try_read` 里检测 `sock.state() != ConnectedState` 时清理。
- **回归**：探针 1 项——写入非法 JSON 后断开，断言 `_pending is None`。
- **风险**：低（仅清理路径）。
