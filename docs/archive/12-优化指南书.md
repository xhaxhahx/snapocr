## 2. P1 必修（6 项）

### P1-01 使用了被 Python 官方弃用的 API

- **位置**：`src/snapocr/i18n.py:216`（`locale.getdefaultlocale()`）
- **后果**：Python 3.11 起弃用、3.15 移除（官方 deprecations 清单，gh-90817）；
  开发/构建机为 **3.12.10**，运行期持续触发 DeprecationWarning；未来升级直接 `AttributeError`。
- **依据**：官方文档 > 内部规范（`docs/10 §4.6`，本轮新增裁定）。
- **建议**：改用 `locale.getlocale(locale.LC_CTYPE)`；Qt 场景优先
  `QLocale.system().name()`（Qt 官方在 Windows 上走 GetUserDefaultLocale，与现行为一致：
  非 en 一律中文）。改完补一条探针：注入 `QLocale` 桩，断言 en/zh 分流不变。
- **回归**：`test_plan_probe` 现有语言用例 + 新探针 1 项。

### P1-02 单实例 IPC 分片到达被当成空命令 → **误触发截屏**

- **位置**：`src/snapocr/utils/singleinstance.py:70-92`（`_try_read`）
- **后果**（**探针实证**）：把 `["--settings"]` 分两片写入（模拟 QLocalSocket 分片），
  服务端收到的是 **`[]`**（第一片 `["--se` 解析失败 → `args=[]` → 静默吞掉）。
  在真实链路里 `_on_command([])` 走 `if not a or "--capture" in a` 分支 →
  **用户什么都没做，框选遮罩弹出**。概率低（小报文通常单片到达）但后果明确。
- **建议**：加读缓冲——`_pending` 改为 `{sock, buf}`，每次 readyRead 累积，
  仅当 `json.loads(buf)` 成功才派发；持续非法数据超过 64KB 才断开。
- **回归**：探针 2 项（整包仍派发、分片拼齐后才派发），复用本轮取证脚本改写。

### P1-03 副屏「悬停自动识别窗口」坐标双重计算 → 副屏功能失效

- **位置**：`src/snapocr/ui/overlay.py:426-439`（`_compute_window_rect`）
- **后果**（**探针实证**）：`mapToGlobal` 返回的已是全局坐标（含屏幕偏移），
  代码又加了一次 `screen_rect.left()`：副屏（左=1920、dpr=1）下传给窗口识别的
  物理坐标是 **(3940, 100)**，正确值应为 **(2020, 100)** —— 主屏（left=0）掩盖了该错误。
  表现为：副屏上悬停不高亮、单击选不中窗口、边缘吸附无目标。
- **说明**：这是**一行 bugfix**，不是 `docs/09` 忽略项 N3/B4「跨屏框选重构」，
  不涉及选区跨屏拖动的结构改造。
- **建议**：`phys = (gp.x() * dpr, gp.y() * dpr)`；反向变换（L433-438）本来就是对的，无需动。
- **回归**：探针模拟左右副屏坐标各 1 项；真机多屏复核 1 次（单屏开发机无法覆盖）。

### P1-04 工具条「线宽档位」未走 i18n（英文界面显示中文）

- **位置**：`src/snapocr/ui/editor.py:57`（`WIDTHS = [(2, "细"), (4, "中"), (8, "粗"), (14, "加粗")]`）
- **后果**：违反红线 §4.3-19（用户可见文案一律 `i18n.tr()` 且中英齐备）。
  `lang=en` 时线宽下拉仍是中文。
- **建议**：档位名改键 `width_thin/width_medium/width_thick/width_bold`，
  `i18n.py` 中英同步；`set_width()` 按索引取文案。
- **回归**：探针 1 项：切 en 后 `width_combo.itemText(i)` 非纯中文。

### P1-05 设置窗「语言」下拉有一项硬编码中文

- **位置**：`src/snapocr/ui/settings_dialog.py:127`
  （`addItem("中文（跟随系统默认）", "")`）
- **后果**：同 P1-04（红线 §4.3-19）；全角括号不在 grep 常规中文区间，历轮漏检。
- **建议**：新增 `lang_default` 键（zh: "中文（跟随系统默认）" / en: "Chinese (follow system)"）。
- **回归**：并入 P1-04 的同一条探针（设置窗 language combo 首项随语言切换）。

### P1-06 CI 的模型下载命令是错的，且被 `|| true` 静默掩盖

- **位置**：`deploy/ci/github-actions.yml:18`
  （`python -m snapocr.download_models || true`）
- **后果**：脚本实际在 `scripts/download_models.py`，`-m snapocr.download_models` 必然
  `ModuleNotFoundError`，`|| true` 把错误吞掉 → **CI 产物永远不带 `resources/models`**，
  与 `docs/04 §1`（"模型是离线发布物，构建一次随包分发"）描述的行为不符。
  运行时虽可回落 wheel 内置模型（功能不坏），但"双份模型"的发布策略在 CI 链路失效。
- **建议**：改为 `python scripts/download_models.py || true`（保留 `|| true`：
  ModelScope 备选失效不应炸流水线，与设计一致）。
- **回归**：CI 触发一次，artifact 内断言 `resources/models/*.onnx` 存在（本地用等价命令验证）。
